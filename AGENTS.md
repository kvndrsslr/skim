# AGENTS.md

Context for agents working in this repository on the first turn.

## What this is

Personal fork of Skim, the macOS PDF reader. The source is a snapshot of upstream 1.7.17 plus the
fork's own commits; upstream itself lives in Subversion, not Git. The fork is published as
`Skim-<version>.dmg` releases on `kvndrsslr/skim` and consumed by the `kxskim` cask in
`kvndrsslr/homebrew-formulae`. User-visible fork features are described in the "Fork change"
section of `README.md`; keep that section current when a change is visible to the user.

## Build and install

Deployment target must be 27.0 (the project files still say 10.13, which the current SDK rejects),
and `PATH` must resolve BSD `/usr/bin/ln` first, because Sparkle's `link-tools.sh` passes `-h`:

```sh
PATH=/usr/bin:/bin:/usr/sbin:/sbin /usr/bin/xcodebuild \
  -project Skim.xcodeproj -scheme Skim -configuration Release \
  -derivedDataPath build/DerivedDataRelease \
  MACOSX_DEPLOYMENT_TARGET=27.0 ARCHS=arm64 ONLY_ACTIVE_ARCH=YES build
```

Product: `build/DerivedDataRelease/Build/Products/Release/Skim.app`. Install it with
`osascript -e 'quit app "Skim"'`, then `ditto <product> /Applications/Skim.app`. The build is
ad-hoc signed; `codesign_skim.sh` is upstream's release signing script.

## Upstream tracking

Upstream is SVN: `https://svn.code.sf.net/p/skim-app/code` (`trunk`, `branches`, `tags`). A local
git-svn mirror lives at `~/src/skim-upstream` (override with `SKIM_UPSTREAM_MIRROR`, cloned from
r15000, which covers the 1.7.x line; 1.7.17 is r16537) and is wired in as the `upstream` remote.

- `main` contains only the fork's commits, rebased onto `upstream/master`.
- `upstream/master` is generated by git-svn; its hashes are rewritten and must never be referenced.
- `./sync-upstream.sh` fetches the mirror, saves the fork commits as patches, rebases `main`, and
  prints a `git range-diff`. Resolve conflicts, build, then `git push --force-with-lease`.
- `git config rerere.enabled true` is expected, so re-syncs reuse earlier conflict resolutions.

Keep fork changes as small topical commits; one giant commit makes every upstream rebase a single
unresolvable blob.

## Conventions and local knowledge

- Commit style follows history: `fix: …`, `fork: …`, `README: …`, with the reason in the body.
- The user evaluates the result. Do not self-certify a fix by measuring screenshots; build,
  install, and ask the user to verify. Report only checks actually run.
- PDFKit is driven through private API in places (`-[PDFView setPageColor:]`, page views,
  `enablePageShadows:`); guard `@available` where the property is version-gated.
- `pageBreakMargins` is ignored and reported as zero unless `displaysPageBreaks` is on, and PDFKit
  does not relayout on a margin change — call `layoutDocumentView` afterwards.
- Page fill comes from `pageColor` (default white). Skim sets it to a dark pane background in
  `SKBasePDFView`, and `SKPDFView` paints page-edge strips in an overlay above the page content.
- Do not commit build products, `build/`, or `.DS_Store` files.
